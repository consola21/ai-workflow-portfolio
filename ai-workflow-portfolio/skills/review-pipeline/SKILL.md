# 검수자 (review-pipeline)

## 0. 쓸지 판단
- 한두 번 검색으로 답이 나오면 스킬 없이 바로 답한다.
- 틀렸을 때 비용이 크거나, 출처가 엇갈리거나, 규정·사실이 최근 바뀌었을 수 있으면 쓴다.
- 질문이 모호하면 범위를 한 줄로 확인하고 시작한다. 요청자가 답할 수 없으면 가정을 적고 진행한다.
- 하위 에이전트를 띄울 수 없으면 혼자 조사한다. 자기 점검은 검증으로 치지 않고, 보고 첫 줄에 "독립 검증 없음"을 적는다.

## 1. 리서처 (하위 에이전트, 가벼운 모델 가능)
- 지시에 목표, 출력 형식, 출처 기준, 작업 경계를 넣는다. 리서처는 대화를 못 보므로 질문·범위·사용처를 전부 적는다.
- 출처만 모은다. 해석·결론 금지.
- 1차 출처 = 그 주장을 처음 만든 기관·문서(법령 원문, 통계 원표, 동료심사 논문, 원 발표, 그 나라 언어의 원문). 막히면 2차로 대신하고 그렇게 적는다.
- 규정·기준은 현행인지 확인한다: 시행일, 개정·폐지·대체, 초안 여부.
- 각 사실에 요지, 근거가 되는 원문 발췌(짧게), URL, 발행일/갱신일/열람일, 출처 종류를 적는다. 못 연 출처는 [미열람], 근거로 쓰지 않는다. 충돌은 양쪽 다 기록.
- 여러 질문은 한 리서처에게 묶는다.

## 2. 분석 (메인)
- 결론마다 근거를 단다. 출처에 없는 세부를 덧붙이지 않고, 다른 문서를 한 문장에 합치지 않는다.
- 확신도: 확인됨(출처가 그 문장을 직접 말함, 출처 종류 병기) / 추론(조합·반대해석·해석) / 모름.
- 법·규범이 걸리면 관할을 전부 꼽는다(당사자가 있는 곳, 물건·데이터가 거치는 곳, 국제 규범). 관할마다 근거를 달고, 못 찾은 곳은 "미확인".
- 결론을 바꿀 빈칸이 있으면 리서처를 한 번 더 띄운다. 재조사는 총 1회, 검증 뒤에는 하지 않는다.

## 3. 검증자 (새 하위 에이전트, 앞 과정을 모름)
- 넘길 것: 원래 질문, 사용처, 결론 문장, 확신도, 근거 URL과 원문 발췌. 메인의 추론 과정은 넘기지 않는다. 결론마다 URL을 달았는지 확인하고 넘긴다. 여러 건은 검증자 하나에게 묶는다.
- 검증 항목(해당 없는 항목은 쓰지 않는다):
  1. 사실: URL을 직접 열어 대조. 출처에 없는 내용, 과한 확신도, 폐지·개정 전 자료로 현행을 단정했는지. URL을 못 열면 그 항목은 "미검증".
  2. 법: 빠진 관할·의무, 근거 없는 법적 단정, 보고가 법률 자문처럼 읽히는지.
  3. 윤리(칸트): 보편법칙 — 이 권고를 모두가 따라도 되는가. 인간성 — 이용자·동료·상대를 수단으로만 쓰거나 위험·확인 부담을 떠넘기지 않는가. 자율 — 결정할 사람이 근거와 한계를 받았는가. 정직 — 모르는 걸 아는 척하거나 확신도를 부풀리지 않았는가.
  4. 사람: 영향받는 사람(이용자·공공)에게 알릴 위험이 빠졌는지.
- 지적마다 근거와 고칠 문장을 낸다. 출처 없이 일반 지식에 기댄 지적은 "미검증"으로 표시한다.

## 4. 보고 (메인)
- 검증 상태는 검증됨 / 수정됨 / 미검증 셋만 쓴다. 메인이 검증자 판정을 뒤집는 건 확신도를 낮출 때뿐이다.
- 핵심 결론이 근거를 잃으면 그 결론은 "조사 불충분"으로 보고하고 재조사 여부를 묻는다.
- 형식: 결론 → 근거·확신도 → 사용처에 바로 쓸 다음 행동 → 남은 확인(확인처, 확인 전 미뤄야 할 결정) → 출처(날짜·종류). 다루지 않은 것은 있을 때만.
