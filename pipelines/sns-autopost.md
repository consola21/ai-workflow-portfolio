# sns-autopost

평일마다 SNS(Threads) 짧은 글 1개를 쓰고, 독립 검증을 거친 뒤, 오전 10시 자동 게시로 예약하고, 운영자 폰으로 검수 알림을 보내는 무인 파이프라인.

```
schedule:  CRON_TZ=Asia/Seoul 8 9 * * 1-5   # 검증 시간을 확보하려고 09:08 실행
connects:  Metricool(예약 게시·이력 조회), Google Drive(주간 캐시), WebSearch
output:    10:00 예약 게시물 + 09:30 이전 검수 알림
```

## 실행 지시 (원본에서 내부 정보만 치환)

평일 아침 자동 실행. 오늘 올릴 글 1개를 쓰고, 독립 검증을 거친 뒤 Metricool로 오늘 10:00(KST) 자동 게시되게 예약하고, 결과를 운영자 폰으로 알린다. 09:30~10:00은 운영자 검수 시간이라 알림이 09:30 전에 꼭 가야 한다. 사람이 없으니 질문하지 말고 끝까지 진행한다.
※ 예약(11번) 전에 맨 아래 '독립 검증'을 반드시 먼저 수행한다.

### 배경
- 계정 주제: 한국 소규모 브랜드가 이미 거래 중인 중국 공장 관리(협상·샘플·생산·납기·검품·선적). 반말 톤.
- 목표: 축은 고정하고 매일 업종과 독자를 바꿔 여러 분야 사람에게 닿기. 답글 낚시성 글은 쓰지 않음.

### 오늘 내용 정하기
1. 오늘 날짜(KST)와 요일을 **코드로** 확인. 토·일이면 종료.
2. 요일별 내용: 월 업종별 흔한 실수와 대응 / 화 "공장이 한 말, 실제 뜻" / 수 무역 용어 하나를 상황으로 풀기 / 목 일반 패턴으로 각색한 짧은 사례 / 금 운영자 시선의 관찰.
3. 업종·독자 — *outreach-targeting 작업과 맞물려 있으니 두 작업을 함께가 아니면 바꾸지 말 것*:
   `n` = 2026-10-12(월)부터 오늘까지 센 평일 수(주말 제외, 10-12가 0)
   - 업종 = `목록[n mod 10]` (반려동물용품, 캠핑용품, 유아용품, 홈트·운동용품, 소형가전, 주방용품, 의류·잡화, 문구·굿즈, 인테리어 소품, 전자 액세서리)
   - 독자 = `목록[(n div 10) mod 5]` (스마트스토어 셀러, 와디즈 메이커, 1인 브랜드 대표, 굿즈 제작자, 무역 처음인 사람)
   - 업종 단어는 글 어딘가에 자연스럽게 반드시 포함.

### 지난주 인기 제품 반영 (주간 캐시)
4. 이번 주 월요일 날짜를 코드로 계산(M). 드라이브 `<CONTENT_FOLDER_ID>` 아래 `_주간인기제품_M.txt`를 찾는다.
   - 있으면 그 목록 사용(검색 안 함).
   - 없으면(보통 월요일 첫 실행) 만든다: 지난주 = M-7 ~ M-1. WebSearch 최대 4회, 그 기간 국내 기사·공식 발표만. **기사 발행일을 반드시 확인하고 기간 밖은 제외.** 형식: `업종 | 품목(브랜드명 없이) | 근거 기사 제목 · 매체 · 발행일 · URL`.
   - 드라이브 실패 시 파일 없이 진행하고 보고에 적는다.
5. 오늘 업종 품목이 목록에 있으면 그 품목을 소재로, 없으면 흔한 품목을 쓰되 인기를 암시하지 않는다.
6. 브랜드명·제품명 금지. 판매 수치를 본문에 옮기지 않는다(근거는 보고에만).

### 최근 글 확인 (쓰기 전에)
7. Metricool `getScheduledPosts`(brand `<METRICOOL_BRAND_ID>`)로 지난 14일치 조회.
   - **오늘 글이 이미 있으면 새로 만들지 않고 종료.** (중복 게시 방지)
   - 최근 5개 글의 모양·첫 문장·마지막 문장·글자 수를 메모해 반복을 피한다.

### 글 쓰기 · 검사
8. 글 모양을 정하고 쓴다.
9. 금지 표현 목록을 지킨다.
10. 다 쓴 뒤 **코드로** 검사: 금지 문자·표현 문자열 검색, 글자 수 범위, 최근 5개 글과 시작·끝 방식 비교. 걸리면 고쳐서 다시 검사. 그다음 독립 검증 → 고친 글로 10번 검사 한 번 더.

### 예약
11. `createScheduledPost`: 오늘 10:00:00+09:00. **실행이 지연돼 이미 09:40 이후면 지금부터 20분 뒤로**(검수 시간 확보).
    - 실패하면 오류를 기록하고 1회만 재시도. **재시도 전에 오늘 글이 생겼는지 다시 조회해 중복 예약을 막는다.**
    - 그래도 실패하면 게시하지 말고 보고에 본문과 오류를 넣어 운영자가 직접 올리게 한다.

### 알림 · 보고
12. 푸시: "스레드 글 검수할 시간 — HH:MM 자동 게시 예정" (실패 시 "예약 실패 — 직접 올려야 해").
13. 보고: 날짜·유형·업종×독자·예약 상태 / 본문 전문 / 글자 수 / 예시 품목 근거 / `검증: 통과 N · 수정 N · 미검증 N` / "HH:MM 전에 고치거나 삭제하면 됨".

### 독립 검증
- Agent 도구로 **앞 과정을 보지 않은 새 하위 에이전트**를 띄운다. 넘길 것: 글의 목적, 본문 전문, 사실 주장마다 근거 URL과 짧은 원문 발췌. **작성 과정·추론은 넘기지 않는다.**
- 검증 항목(지적마다 근거와 고칠 문장, 300단어 이내): 사실(URL 직접 대조) / 법(한국·중국·국제 규범) / 윤리(칸트) / 독자에게 알릴 위험.
- 지적대로 고친다. 출처 없는 지적은 "미검증"으로 보고.
- **마감 09:28.** 그때까지 안 끝나거나 Agent 도구가 없으면 검증 없이 예약으로 넘어가고 보고에 "독립 검증 없음".
